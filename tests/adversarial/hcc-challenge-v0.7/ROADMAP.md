# Extension phase: maximum three adversarial releases

Original v0.6 (724 cases, closed 15 November) remains immutable. This is a distinct follow-on experiment pinned to a new feature baseline, not a reopening of the original result. Use independent first-run freezing and tests-first fixes in each round; preserve earlier challenges unchanged. A release is not a new compiler version. Proposed numbering v0.7, v0.8, v0.9 identifies extension challenges only.

| Round | Focus | Exit evidence |
|---|---|---|
| 1 — v0.7 (this release) | 65 independent deterministic tests across C11 alignment/TLS/K&R/tgmath/VLA/atomics/threads and selected GNU language and builtin/attribute features. Basic mixed-TU and concurrency cases. | Frozen first run and post-fix results at O0/O2, both mixed directions, no unexpected regressions in closed v0.6 or existing harness. |
| 2 — v0.8 (conditional on v0.7) | Deeper interaction tests guided by observed failure families: atomics of supported widths including 16-byte, aggregate and extended floating atomics, compare-exchange and RMW, memory-order IR evidence where observable (not asserting equality to a weaker order), TLS/atomic/VLA interactions; deterministic stress of concurrent mutex, condition, once and TSS behavior. Mixed compiler ABI with new features; target-specific type/record layout and native runtime probes for Linux, Apple and Windows, including LLP64 vs LP64, Apple arm64 long double and the project's documented stand-in boundaries. | Frozen results with separate native and proxy matrices, link-runtime selection and evidence, no claimed native result from stand-ins. |
| 3 — v0.9 (only if useful) | Final holdout focused on remaining risks and unfamiliar interactions, generated/differential tests within the supported language contract, metamorphic transformations, IR assembly checks, optimisation-sensitive stress, and representative native application regression runs. | Immutable extension baseline, all in-scope gating defects resolved or expressly accepted as limitations, no unexpected regressions, explicit open issues and evidence limitations. |

The later releases are plans, not generated or executed tests. Their concrete contents depend on the frozen first runs. Avoid another release solely to inflate the test count. Stop after round 2 if the evidence is adequate, and in all cases stop after round 3. Retesting repairs is not an extra adversarial release; it is part of the same round. Report C11 portable constraints, implementation-defined target choices, GNU extension contracts and separate exploratory observations without conflating them. The feature advertising macros being enabled do not prove complete optional-feature conformance.

## Deliberately documented limits (not new bugs)

The supplied pack records `_Complex` absent and `__STDC_NO_COMPLEX__=1`; only real tgmath is claimed. Atomic supported size set is 1/2/4/8/16, no locking runtime; consume is strengthened to acquire (flag-clear exception) and nonconstant order is evaluated then lowered to seq_cst. VLA `static`/qualifiers inside brackets are not implemented; computed goto into a VM scope is not fully diagnosed. The GNU unsupported-feature list and nonprototype conversion deviation in REVIEW-GUIDE §13 remain out of scope as new defects. Linux glibc `<pthread.h>` alignment-typedef compatibility is documented; tests use `<threads.h>`. Apple stand-in emulated TLS is not native Darwin TLS. Some limits represent partial C11 support even though feature-test macros advertise the facilities; they should be recorded as limitations rather than silently treated as conformance.

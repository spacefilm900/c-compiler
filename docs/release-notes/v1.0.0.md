# hcc 1.0.0

The first release of **hcc**, the Haviland C Compiler: a clean-room C11
compiler written in Rust that emits textual LLVM IR, with Clang/LLVM as the
back end.

## Highlights

- **C11** (N1570), except the optional complex number types (`_Complex`).
  A clause-by-clause audit of clauses 5 to 7 passes 286 of its 288 probes
  (54 programs and 234 constraint or syntax violations), compared against
  `clang -std=c11 -pedantic-errors`. The other 2 are one known
  gap: the 6.7.4p3 inline-definition constraints are not diagnosed (see
  `docs/C11_CONFORMANCE.md`). This is not a formal certification. The
  compiler supports the harder parts: variable-length
  arrays, `_Atomic` and `<stdatomic.h>`, `<threads.h>`, `_Generic`,
  `_Alignas`, `_Thread_local`, `_Static_assert`, Unicode literals,
  universal character names in identifiers (and UTF-8 identifiers),
  old-style K&R function definitions and `<tgmath.h>`. Its other
  limitations are listed in the user guide.
- **GNU C** with `-std=gnu11`: the extensions that real programs and the
  Linux and macOS system headers use.
- **Six targets**: Linux x86-64 and arm64, macOS arm64 and x86-64, and
  Windows x64 (MSVC and MinGW-w64), each with its platform ABI.
- **Real programs**, built by hcc and checked against Clang builds in CI:
  DOOM (frame for frame), Lua 5.4.7, SQLite 3.54.1, QuickJS (its tests and
  test262), zlib, and One True AWK.
- **Tested hard**: the Writing a C Compiler suite, the GCC torture tests,
  Csmith and YARPGen random programs, 969 adversarial cases, fuzzing of the
  compiler itself, coverage and mutation testing, and a weekly run on real
  arm64 Linux, macOS and Windows machines. The figures, each with what it
  counts:
  - Csmith: 3,000 programs generated, 2,775 compared at `-O0` and 2,774 at
    `-O2` (the rest did not finish under both GCC and Clang), 0 mismatches.
  - YARPGen 2: 2,000 programs generated, 1,651 compared (the rest failed
    in Clang's reference run), 0 mismatches.
  - The adversarial kits: all 969 cases pass at `-O0` and `-O2`: v0.6
    (724 cases), v0.7 (65), v0.8 (80) and v0.9 (100).
  - Mutation testing, on 7 selected source files and an earlier commit:
    92.9% of the 1,429 viable mutants caught, 96 missed, 5 timeouts.
  - The figures above, except mutation testing, come from the rerun of
    every suite on the release-candidate commit `2e80ec0`
    (`reports/release-1.0/README.md`).

## Platforms

| Target | Every pull request | Real platform | `<threads.h>` |
| --- | --- | --- | --- |
| Linux x86-64 | native: every suite | the same | glibc |
| Linux arm64 | native quick job, and the harness under qemu | native, nightly and weekly | glibc |
| macOS arm64 | emulated: IR and Mach-O checks, the harness under qemu with Apple's calling convention | native after merges and weekly | fallback runtime (`lib/threads.c`) |
| macOS x86-64 | emulated: IR and Mach-O checks and a Linux stand-in | native, by hand only | fallback runtime |
| Windows x64, MinGW-w64 | emulated under Wine | native, weekly and by hand | fallback runtime |
| Windows x64, MSVC | emulated: the MSVC type model under Wine, IR and COFF checks | native (MSVC and UCRT), weekly and by hand | fallback runtime |

"Fallback runtime" is hcc's own `lib/threads.c` over POSIX threads or
Win32. On those platforms the thread tests compare hcc's build of it with
Clang's build of the same runtime.

## Provenance

hcc was written from N1570, the LLVM Language Reference, the platform ABI
documents and the public GCC manual. Clang and GCC were used only as black
boxes; no compiler or C library source was consulted. This records how the
code was produced. It is not a certification. See the README's
"Clean-room provenance" section.

## New in this release

- `hcc --version`, and a regrouped `hcc --help`.
- `hcc --link`: compile and link a program in one command, with
  `lib/threads.c` and `-pthread` added automatically when a program uses
  `<threads.h>` on a platform that needs them.
- Messages show the source line with a caret; command-line errors say what
  is wrong.
- Trigraphs, `__DATE__` and `__TIME__` (with `SOURCE_DATE_EPOCH` for
  reproducible builds), and the `_Pragma` operator.
- GNU forward-declared enums are incomplete until defined, as in GCC and
  Clang (#68).
- Universal character names in identifiers (#76) and multi-character
  character constants.
- The C11 conformance audit (`docs/C11_CONFORMANCE.md`). It fixed one
  macro-rescanning bug and tentative definitions of `int a[];`. It also
  added the missing diagnostics for 10 constraint violations.
- A user guide, a language reference, a changelog, and contributing and
  security policies.

threads runtime (`lib/threads.c`), the user guide, the changelog and the
licence. Check downloads against `SHA256SUMS`. hcc needs Clang/LLVM 18 or
newer to turn its IR into programs; see `docs/USER_GUIDE.md`.

## Known limitations

No `_Complex`; the 6.7.4p3 inline-definition constraints are not
diagnosed; no object
files or debug information of its own (Clang does that step); inline
assembly only without operands. The user guide
lists the rest.

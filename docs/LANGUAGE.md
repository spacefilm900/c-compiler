# The language hcc accepts

This is the detailed reference for what hcc accepts and rejects: the C11
subset, the GNU extensions, and the input it does not accept. The
[user guide](USER_GUIDE.md) is the shorter, task-oriented introduction.

Type sizes, calling conventions and predefined macros below are those of
the original target, x86-64 Linux (LP64, System V). The other targets
differ where their ABIs do (for example, `long` is 32 bits on Windows,
and the `long double` format differs from target to target); see
[user guide section 6](USER_GUIDE.md#6-targets).

## C11 subset

- One translation unit of function definitions, prototypes, and file-scope objects. The integer types are the LP64 sizes: `char` (signed), `signed char`, and `unsigned char` are 8 bits; `short` and `unsigned short` are 16; `int` and `unsigned int` are 32; `long`, `unsigned long`, `long long`, and `unsigned long long` are 64. `void` is a return type and the sole unnamed parameter (`int main(void)` and `int main()` are both no-parameter definitions). Specifiers may appear in any legal order (`unsigned long long int`, `int long unsigned`). `signed` alone is `int`. `unsigned` alone is `unsigned int`. Invalid combinations are diagnostics. `char` and `signed char` are not the same type.
- Prototypes: `int f(void);`, `char id(char c);`, unnamed parameters (`int f(int, char);`), and a trailing ellipsis on a declaration (`int printf(const char *, ...);`). A later definition may use different parameter names. The types must match, including the return type and whether the function is variadic. A call checks the argument count. Fixed arguments are converted as if assigned to the parameter. Arguments past the fixed parameters get the default argument promotions (`char` and `short` become `int`, and `float` becomes `double`). A function declared but not defined is an LLVM `declare`, so an external definition can be linked in. `static` on a file-scope function gives it internal linkage. A call to a function that has not been declared is an error. C11 has no implicit function declarations. A definition may end in `...` when it has a named parameter. `<stdarg.h>` implements `va_start`, `va_arg`, `va_end`, and `va_copy`.
- On this target, `char`, `signed char`, and `short` parameters and return values are passed with LLVM `signext`. `unsigned char` and `unsigned short` use `zeroext`. That is the System V AMD64 rule that those values are extended to 32 bits. `int` and wider types have no extension attribute.
- `const` and `volatile` on declaration specifiers and after `*` (`const char *`, `char *const`, `const int`). The same qualifier twice in one list is a diagnostic. Assigning to a const-qualified object, including `*p` when `p` has type `const char *`, is a diagnostic. `char *` may be passed to a `const char *` parameter. `const char *` may not be passed to `char *`, and `char **` may not be passed to `const char **`. Top-level `const` on a parameter is not part of the function type. `volatile` is a `load volatile` or `store volatile`, and a volatile aggregate copy tells `llvm.memmove` the copy is volatile. `restrict` is a qualifier on a pointer: it participates in compatibility and assignment, it is dropped from a parameter's function type the same way top-level `const` is, and it does not change the IR. `restrict` on a non-pointer is a diagnostic.
- File-scope objects of those integer types, of `float` and `double`, of pointers, and of arrays: `char g;`, `unsigned long g = expr;`, `float f = 1.5f;`, `double d = 1.5;`, `int *p = &g;`, `int a[4] = {1, 2};`, `int b[] = {1, 2, 3};`, `char s[] = "hi";`, `char *msg = "hi";`, `extern int g;`, and `static short g;`. Several declarators are allowed, and `*` belongs to each declarator (`int *a, b` is one pointer and one `int`). A declaration without an initialiser and without `extern` is a tentative definition; if nothing in the file initialises it, it is zero (a null pointer, or `zeroinitializer` for an array). `extern` without an initialiser does not define the object. An integer initialiser is an integer constant expression. A `float` or `double` initialiser is a floating constant expression. A pointer initialiser may also be an address constant (`&g`, `&a[2]`, `a + 1`, or a string literal) or a null pointer constant. A const object is an LLVM `constant`. Locals and parameters shadow globals.
- Locals and `for (char c = ...)` declarations, with optional initialisers. A block may also declare `static int x = 1` (a constant initialiser, no linkage, the value persists across calls) and `extern int g` or `int f(int)` (linkage follows C11 6.2.2, and the name is not visible after the block). `static` and `extern` are not allowed on a `for` header, and a block-scope function cannot be `static`. The initialiser is converted to the variable's type. Arrays use a brace list. A partial list zeros the rest. `int a[] = {1, 2, 3}` gets its length from the list. A character array may also be initialised from a string: `char s[] = "hi"` is three bytes including NUL, `char s[10] = "hi"` zero-fills, and `char s[2] = "hi"` has no NUL. A longer string is a diagnostic.
- Statements: blocks, expression statements, empty statements, `return`, `if` / `else` (an `else` binds to the nearest `if`), `while`, `do` / `while` (`continue` jumps to the condition), `for`, `break`, `continue`, `switch` / `case` / `default`, and `goto` with a label in the same function. The controlling expression is promoted. Each case constant is converted to that type. Labels may be nested inside the body, and `break` leaves the switch. The IR is an LLVM `switch`. A `goto` target is a block named `C.<label>`.
- Pointer declarators, including `int **pp`, `int *a[3]`, and `int (*p)[3]`, plus `void *`. Unary `&` and `*`. Subscripts `a[i]` and `i[a]`. Array-to-pointer decay except under `sizeof` and `&`. Pointer plus or minus an integer, scaled by the element size. Pointer minus pointer, with type `long`. Pointer equality, including null and `void *`, and relational comparisons of compatible pointers. `++`/`--` on pointers (one element), and `+=`/`-=` on pointers (as many elements as the right operand). Pointers in `if`, `!`, `&&`, `||`, and `?:`.
- Expressions, with C precedence and associativity: integer constants (decimal, octal, hexadecimal, with `u`/`U`, `l`/`L`, `ll`/`LL`, and the combined suffixes), floating constants (decimal and hexadecimal, with an optional `f`/`F` suffix), character constants (`'a'`, `'\n'`, `'\0'`, `'\x41'`, `'\101'`), string literals (`"hi"`, `"\n"`, `"\x41"`, `"hel" "lo"`), identifiers, parentheses, casts (integers, `float` and `double`, pointers, and between an integer and a pointer), unary `+` `-` `!` `~` `&` `*`, binary `+` `-` `*` `/` `%` `&` `|` `^` `<<` `>>`, comparisons, `&&` and `||`, `?:`, assignment and compound assignment, prefix and postfix `++`/`--`, the comma operator, `sizeof` on an expression or a type (including `sizeof(int *)`, `sizeof(int[3])`, and `sizeof "abc"`, which is 4), and direct calls, including variadic calls. Pointers and arrays may be parameters and return types. An array parameter is adjusted to a pointer. An ordinary or `u8` string literal has type `char[N]` including the terminating NUL and decays to `char *` except under `sizeof` and `&`. A `u` string is `char16_t[N]`, a `U` string is `char32_t[N]`, and an `L` string is `wchar_t[N]` (`wchar_t` is `int`). Each decays to a pointer to its element type except under `sizeof` and `&`. The address is a private unnamed_addr constant. Modifying that object is undefined and is not diagnosed.
- Integer promotions and the usual arithmetic conversions apply. Types narrower than `int` promote to `int`. Unsigned arithmetic wraps. Signed `/` and `%` round toward zero; unsigned `/` and `%` use `udiv` and `urem`. Comparisons and `&&` / `||` produce `int` 0 or 1. `-1 < 1u` is false. `&&`, `||`, and `?:` evaluate only the operands that C evaluates.
- The operand of `sizeof` is not evaluated, except when its type is a variable-length array: then the array bound is evaluated, so `sizeof(int[n++])` increments `n`. Its result type is `unsigned long`, and `sizeof(sizeof(int))` is 8. `sizeof(void)` and `sizeof` of an incomplete array are rejected. `sizeof(int *)` is 8. `sizeof` of an array is the element size times the length, not the size of a pointer.
- A signed right shift is arithmetic. An unsigned right shift is logical. A shift count outside `0 .. width` of the promoted left operand, a signed left shift of a negative value, and a signed left shift that does not fit are undefined. Constant initialisers reject those shifts. A runtime shift is emitted without a count mask and without a diagnostic.
- `++`/`--` and compound assignment require an lvalue. On an integer, the operation uses the promoted type and the result is converted back. On a pointer, `++` and `--` move by one element, and `+=` and `-=` by as many elements as the right operand. Compound assignment evaluates the right-hand side, then loads the lvalue once.
- Converting an out-of-range value to a signed type keeps the low bits and interprets them as two's complement, matching Clang on this target. `(char)1000` is `-24`. Character constants whose byte is above 127 are negative because `char` is signed: `'\xff'` is `-1`. Converting an integer to a pointer extends it to 64 bits and uses those bits as the address. Converting a pointer to an integer keeps the address bits, truncated if the integer is narrower than 64. `(int *)(int)-1` and `(int *)(long)-1` are the same all-ones address. `(int *)(unsigned)-1` is the low 32 bits only.
- Assigning a pointer requires a compatible pointer, a qualification conversion (`char *` to `const char *`, and the same rule for `volatile`), `void *` in either direction when the destination does not drop a qualifier, or a null pointer constant (`0` or `(void *)0`). `int *` and `char *` are not compatible. Dropping `const` is an error here. Clang warns and still compiles. A cast may drop a qualifier; that is not diagnosed.
- A function may call itself, and it may call a function that was declared earlier and defined later. Assignment targets are variables; parentheses do not change that (`(x) = 1` assigns to `x`).
- Tagged structs at file scope and block scope. Members may be any supported type: integers, pointers, arrays, and nested structs, including a struct declared in the member list. `struct node;` is an incomplete type. A pointer to it is complete, so a struct may contain a pointer to itself. An object of an incomplete struct type is a diagnostic, as is `sizeof` of that type. `extern struct S x;` is the exception: it may name an object completed in another translation unit. Layout follows the System V AMD64 ABI: each member is aligned to its alignment, the struct alignment is the strictest member alignment, and the size is rounded up to that alignment. An array member uses the element alignment. The extra 16-byte alignment applies to a local or global array variable, not to a member. `.` and `->` name a member, including chains (`a.b.c`, `p->next->val`), and the result is an lvalue when the base is. `&s.x` and `s.arr[i]` work. A whole struct may be assigned, which copies every byte, including padding. Brace initialisers work for structs and for arrays of structs, at local and file scope. A missing member is zero. A nested brace initialises one member. A flat list fills inner aggregates in order. An expression of the member's struct type initialises that member as a whole (`struct Line line = {p, q}`). Designated initialisers (`.x = 1`, `[0] = 1`) are accepted. The next positional initialiser continues at the next subobject. Bit-fields (`int x : 3`) pack least-significant bit first. A zero-width unnamed bit-field aligns the next field and does not raise the struct's alignment, so `struct { char a; int : 0; char b; }` has alignment 1. A file-scope or local initialiser may nest a bit-field struct inside another struct or an array. A plain member of that nested struct is part of the same byte image. A struct with a const member cannot be assigned as a whole. A complete struct or union may be passed or returned by value. Aggregates of at most 16 bytes whose fields are integers, pointers, `float`, or `double` are coerced to register pieces. An argument is `byval` when it is larger, unaligned, or the registers it needs are already taken. A return is `sret` only when its class is memory; a register-classified return still uses the return registers. `f().x`, assignment from a call, and `?:` on a struct copy the result. An SSE eightbyte is passed in an XMM register. A return whose eightbytes are `X87` then `X87UP` is `x86_fp80` in `%st0`. Other aggregates that contain `long double` are `sret`. The last member of a struct that already has another named member may be a flexible array. `sizeof` excludes it. Initialising it is a diagnostic, and that struct is not an array element or a member of another struct. A prototype may name an incomplete struct; a definition and a call need a complete type.
- `//` line comments and non-nesting `/* */` block comments. A backslash immediately before a new-line is deleted first (C translation phase 2), including inside a comment or a string, so the following physical line is part of the same logical line. `__LINE__` is the physical line of the token.
- A built-in preprocessor. `#define` / `#undef` cover object-like macros and function-like macros, including an empty parameter list and `__VA_ARGS__`. The `(` must follow the name with no space for the definition to be function-like. `#` stringifies an argument and `##` pastes two tokens. Expansion rescans, and a macro is not expanded again inside its own replacement. An identical redefinition is allowed; a different one is a diagnostic. `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else`, and `#endif` nest. `#if` expressions are evaluated in `intmax_t` / `uintmax_t`. `defined X` and `defined(X)` are recognised, and any other identifier is 0. A group whose condition is false is skipped: macros there are not expanded and `#error` there is not fired. `#include "file"` searches the including file's directory, then each `-I` directory, then the compiler's `include/`, then the host directories. `#include <file>` searches `-I` directories, then `include/`, then `/usr/include/x86_64-linux-gnu` and `/usr/include`. `#include_next` resumes after the directory that provided the current file. The nested-include limit is 200. `#error` is a diagnostic. `#line` is accepted. `#pragma once` is honored; any other `#pragma` is ignored. A line that is only `#` is a null directive. Predefined names include `__FILE__`, `__LINE__`, `__STDC__` (1), `__STDC_VERSION__` (`201112L`), `__STDC_HOSTED__` (1), `__x86_64__`, `__linux__`, `__LP64__`, `__SIZE_TYPE__`, and `__USER_LABEL_PREFIX__`.
- `typedef` names an existing type, including a pointer, an array, a struct or union, or a function type. A typedef is an alias: `typedef int T` and `int` are the same type. The parser resolves the typedef-name versus identifier ambiguity with a scope stack.
- Enumerations. `enum E { A = 1, B }` defines `A` and `B` as `int` constants. The enumerated type is compatible with `unsigned int` when every value is nonnegative and with `int` when one is negative, as with GCC and Clang (C11 6.7.2.2p4 leaves this to the implementation). On the MSVC target it is `int` in both cases, as with Clang there. Values that do not fit in `int` are a GNU extension, and strict C11 rejects them. Under that extension, a list of nonnegative values up to `UINT_MAX` gets `unsigned int`, the same width as `int`. A larger nonnegative list gets a 64-bit unsigned type, and a list with a negative value gets a 64-bit signed type. In these cases the constants also take the enumerated type. An anonymous `enum { RED, GREEN }` introduces the constants only.
- Unions. Members start at offset 0. The size is the largest member, rounded up to the strictest alignment. `.` and `->` name a member. A brace initialiser initialises the first member. Assignment copies every byte. A forward `union U;` is an incomplete type, and a pointer to it is complete.
- `_Bool` (and `<stdbool.h>`'s `bool`, `true`, and `false`). A nonzero value converts to 1. `restrict` is a pointer qualifier and does not change the IR. Function pointers may be declared, assigned, compared with `==` and `!=`, stored in arrays and structs, and called as `fp(...)` or `(*fp)(...)`. A function designator decays to a pointer. `typedef` of a function type works. `qsort` takes a comparator. Relational `<` on function pointers is a diagnostic. `float`, `double`, and `long double` are computed, including constants, conversions, and the System V calling convention. `long double` is 80-bit extended precision. A scalar parameter is passed in memory and a scalar return uses the x87 stack.
- `__attribute__((...))` and `__extension__` are accepted; [GNU extensions](#gnu-extensions) lists the attributes that have a meaning. `__asm__("name")` is the linker name of a function.

`include/` holds headers a compiler supplies rather than the C library: `stddef.h` (`size_t`, `ptrdiff_t`, `wchar_t`, `NULL`, `offsetof`), `stdarg.h` (`va_list` and the `va_*` macros, lowered to the builtins), `stdbool.h`, `stdnoreturn.h` (`noreturn`), `stdalign.h`, `stdatomic.h`, `tgmath.h`, `iso646.h`, `float.h` (IEEE binary32, binary64, and the `LDBL_*` macros), and `limits.h` (the ISO limits for this LP64 target). `#include <stdio.h>` and the other library headers come from the host. Clang, when it compiles the same test, uses those same host headers. An `l`/`L` floating constant is an 80-bit extended value, so `float.h` can name `LDBL_MAX` and a program can use that value.

Reaching the closing brace of an integer function lowers to a return of 0 of that type. That is what C requires for `main`. A `float` or `double` function that falls off the end lowers to a return of `0.0`. A `void` function that falls off the end lowers to `ret void`.

## GNU extensions

These follow the public GCC manual, with GCC 14 and Clang 19 used only as black boxes. No compiler source was read.

**Only with `-std=gnu11`.** Strict C11 rejects each of these with an `error:` that names `-std=gnu11` (or, for `typeof`, treats the plain word as an identifier):

- `typeof` and `__typeof__` (`__typeof`), with a type name or an expression operand. The expression is not evaluated. A bit-field operand is an error.
- Statement expressions `({ ... })`. The value is the last expression statement's value (unqualified, after lvalue conversion), or `void`. They are allowed only inside a function. Labels and `goto` inside one work.
- Range designators `[first ... last] = value` in array initialisers set every element in the range.
- Case ranges `case low ... high:`. An empty range warns ("empty case range specified"), and an overlap with another case is an error. Ranges of fewer than 256 values are expanded into the `switch`; wider ones become a range test before the default.
- Zero-length arrays `T a[0]`, including as the last member of a struct; the array adds no size.
- `x ?: y`, which evaluates `x` once and yields it when nonzero.
- Empty initialisers `= {}`, treated as `= {0}`.
- Labels as values: `&&label` is the address of a label in the current function, of type `void *`, and `goto *expr;` jumps to it. A label address is a constant in a block-scope `static` initialiser, so a dispatch table such as Lua's `static const void *const disptab[] = { &&L_OP_MOVE, ... };` works. A computed `goto` may reach any label of the function whose address is taken (an address taken only inside `sizeof` does not count). Differences of label addresses (`&&a - &&b`) are not supported. Use a label address only to jump to it or to compare it with a null pointer: LLVM, the backend, leaves an equality test between two label addresses undefined, so such a comparison compiles but its result is not promised.

**In both modes** (these spellings are reserved for the implementation, C11 7.1.3):

- `__attribute__((...))` on declarations, declarators, types, record members, functions, parameters, labels, and as a null statement. With meaning: `noreturn`, `unused`, `used` (`@llvm.used`), `aligned` / `aligned(N)` on objects, members, and struct or union types, `packed` on a struct or union or a member, `always_inline` / `noinline`, `gnu_inline`, `section("name")`, `weak` (definitions and `extern_weak` declarations), `deprecated` / `deprecated("msg")` (a call warns), `cold` / `hot`, `const` / `pure` (LLVM `memory(none)` / `memory(read)`), `constructor` / `destructor`, and `mode(QI|HI|SI|DI|word|pointer|byte)`. Accepted and ignored: `format`, `nonnull`, `noclone`, `nothrow`, `returns_twice`, `malloc`, `warn_unused_result`, `visibility`, `may_alias`, `transparent_union`, and similar optimisation hints. An unknown attribute is ignored with the warning `unknown attribute 'X' ignored`. These are an error because ignoring them would change behaviour: `vector_size`, `cleanup`, `alias`, `ifunc`, `naked`, and `weakref`. `aligned` on a typedef is allowed only when it does not change the alignment, and a bit-field in a struct whose layout `packed` or `aligned` changes is an error.
- `__int128`, `signed __int128`, `unsigned __int128`, `__int128_t`, and `__uint128_t`: 128-bit integers, size and alignment 16, lowered to LLVM `i128`; constant expressions keep all 128 bits. A parameter, return, or `va_arg` uses two general-purpose registers and 16-byte stack alignment. `__builtin_add_overflow` and friends accept 128-bit operands and destinations. Bit-fields of these types are not supported.
- An empty declaration at file scope (a lone `;`). C11 does not allow it; Clang and GCC accept it.
- `inline` follows C11 6.7.4p7: when every file-scope declaration of a function has `inline` and none has `extern`, its definition is an inline definition, emitted `available_externally` (calls may inline it, and otherwise call the external definition from another file or library). `__attribute__((gnu_inline))` and the `-fgnu89-inline` option give GCC's GNU89 rules instead: an `extern inline` definition is only for inlining and a plain `inline` one is external; `-fgnu89-inline` also predefines `__GNUC_GNU_INLINE__` in place of `__GNUC_STDC_INLINE__`. The macOS SDK's `<ctype.h>`, `<math.h>` and `<stdio.h>` define functions this way.
- `__extension__`, `__inline__` / `__inline`, `__signed__`, `__const__`, `__volatile__`, `__restrict__`, `__alignof__` (with a type or an expression), `__asm__` labels, and `__FUNCTION__`.
- Builtins folded to constants: `__builtin_constant_p` (1 for an integer constant expression, a floating constant or a string literal, otherwise 0), `__builtin_types_compatible_p` (top-level qualifiers ignored), `__builtin_choose_expr`, `__builtin_offsetof`, and the bit builtins below when their operand is constant.
- Builtins lowered to LLVM: `__builtin_expect`, `__builtin_unreachable`, `__builtin_trap`, `__builtin_clz` / `ctz` / `popcount` / `parity` / `ffs` / `clrsb` with their `l` and `ll` forms, `__builtin_bswap16` / `32` / `64`, `__builtin_alloca`, `__builtin_prefetch` (no code), `__builtin_assume_aligned`, `__builtin_return_address(0)`, `__builtin_frame_address(0)`, `__builtin_isnan` / `isinf` / `isfinite` / `isnormal`, the `va_*` builtins, and the overflow builtins: generic `__builtin_add_overflow` / `sub` / `mul` on any integer operands, and the typed `__builtin_sadd_overflow`, `__builtin_uaddl_overflow`, `__builtin_smulll_overflow`, and the rest of that family.
- Library forwarders: `__builtin_abort`, `__builtin_exit`, `__builtin_printf`, `__builtin_memcpy` and the other string and memory functions, `__builtin_malloc`, `__builtin_abs` / `labs`, the `<ctype.h>` functions, and the `<math.h>` functions with their `f` and `l` forms (for example `__builtin_fabs`, `__builtin_sqrtf`). Each is a call to the library function of the same name without the prefix, with that function's standard prototype. GCC accepts some forwarders that Clang does not, such as `__builtin_exit` and the `<ctype.h>` ones; for those, the output was checked against GCC.

Not yet: `__builtin_classify_type`, `__builtin_*_overflow_p`, `__builtin_setjmp` / `longjmp`, `__builtin_apply`, vector types, inline assembly with operands, nested functions, and implicit `int` and implicit function declarations.

## Not accepted

Unsupported or invalid input is a diagnostic. It is not ignored and it is not lowered.

Trigraphs are replaced in strict C11, and under `-std=gnu11` only with `-trigraphs`. `_Pragma` is carried out as a `#pragma` line. `__DATE__` and `__TIME__` are defined, from `SOURCE_DATE_EPOCH` when it is set. `L`, `u`, `U`, and `u8` string literals are accepted, as are `L`, `u`, and `U` character constants. `wchar_t` is `int`, `char16_t` is unsigned 16-bit, `char32_t` is unsigned 32-bit, and a `u8` string is an array of `char`. `u8'...'` is rejected. Inside a character constant or string literal, a non-ASCII source character (UTF-8) or a universal character name (`\u`, `\U`) is encoded for the prefix: UTF-8 for an unprefixed or `u8` string, UTF-16 for `u`, UTF-32 for `U` and `L`. A character constant whose character needs more than one code unit is a diagnostic. A prefixed character constant in `#if` has the value and type it has in program text, so `L'\400'` is 256. Identifiers may contain universal character names and UTF-8 characters from C11 Annex D (D.2 combining marks not first); a UCN and the UTF-8 character spell the same identifier, stored and emitted as UTF-8 (a quoted LLVM name such as `@"caf\C3\A9"`). A UCN for a character below U+00A0 (other than `$`, `@` and `` ` ``), a surrogate or a value above U+10FFFF is a diagnostic, and so is any character outside Annex D in an identifier (including `$`). Binary literals and other non-ASCII characters outside literals, comments and identifiers are errors. An integer suffix that is not in the C11 grammar (`1Ll`, `1uu`) is a diagnostic. An integer constant that fits in no type on the C11 6.4.4.1 list is a diagnostic, including a decimal value that does not fit in signed `long long`. A multi-character character constant (`'ab'`, C11 6.4.4.4p10) is an `int` whose value is implementation-defined; hcc, like GCC and Clang on every hcc target, shifts each byte in from the right and keeps the last four (`'ab'` is `0x6162`), with a warning, and one more warning past four characters. A multi-character `L`, `u` or `U` constant is a diagnostic, as in Clang. Hex or octal escapes outside `unsigned char` are diagnostics. A wide hex escape must fit in `unsigned int`.

The parser or checker rejects a `static` or `extern` declaration in a `for` header, a `static` function declaration at block scope, a non-empty identifier list on a declaration that is not a definition (`int f(a, b);`), nested functions, a variadic function with no named parameter (`int f(...);`), an incomplete struct or union passed or returned at a definition or a call, empty structs and unions, a GNU range designator (`[0 ... 3]`) in strict C11 (it needs `-std=gnu11`), computed `goto` and `&&label` in strict C11 (they need `-std=gnu11`), and a label followed by a declaration (`case 1: int x;`). It also rejects `auto` and `register` at file scope, `&` of a `register` object, `inline` or `_Noreturn` on `main`, a function definition that takes its function type from a typedef, the `_Atomic` qualifier on an array or function typedef, `__VA_ARGS__` in a macro that is not variadic, and `#undef` of the predefined macros of C11 6.10.8.1. A file-scope `int a[];` that no later declaration completes is an array of one element, with a warning (C11 6.9.2p2). An inline definition that breaks C11 6.7.4p3 (a modifiable `static` object, or a use of an identifier with internal linkage) is not diagnosed. An untagged unnamed struct or union member is anonymous: its members are members of the enclosing type. A tagged unnamed member is still a diagnostic. Arithmetic on `void *` is rejected; Clang warns and treats the size as 1. A global initialiser that is not an integer or floating constant expression, an address constant, or a constant brace list of those is a diagnostic. Assignment, `++`/`--`, calls, and the comma operator are not allowed in that constant expression when they are evaluated (C11 6.6). An evaluated division by zero is a diagnostic, and so is an evaluated signed constant whose result does not fit in its type (C11 6.6p4), including `INT_MIN / -1` and `1 << 31`. `int f();` declares a function without a prototype: a call applies the default argument promotions, and compatibility with a prototype follows C11 6.7.6.3p15. Compound literals, `_Generic`, `_Static_assert`, `_Alignof(type-name)`, `_Alignas`, `_Thread_local`, old-style K&R definitions, variable-length arrays (including variably modified types), `_Atomic`, `<stdatomic.h>`, and `<threads.h>` are supported. `__STDC_NO_VLA__`, `__STDC_NO_ATOMICS__`, and `__STDC_NO_THREADS__` are not defined. Lock-free atomic objects are 1, 2, 4, 8, or 16 bytes and are aligned to at least their size; a larger atomic type is a diagnostic. On x86-64, 16-byte atomics carry `+cx16` in the IR so the documented `clang -w` link needs no libatomic. `_Complex` is still recognised so it produces a specific "not supported" diagnostic. `__STDC_NO_COMPLEX__` is predefined. On a Linux target, `<threads.h>` is the C library's own header when it exists (glibc 2.28 and later); link with `-pthread`. If the C library has no `<threads.h>`, and on macOS and Windows, hcc supplies typedefs and prototypes in `include/threads.h` and a small original runtime in `lib/threads.c` over pthreads or the Win32 thread API. Compile and link `lib/threads.c` with the program, and on POSIX also pass `-pthread`. The runtime does not include `<pthread.h>`, because hcc rejects glibc's aligned typedef of pthread typedefs. The `__builtin_*` functions hcc knows are listed under [GNU extensions](#gnu-extensions); any other `__builtin_*` name is an ordinary undeclared identifier.
